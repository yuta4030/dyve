# dyve

仕事が思考になった人のための、潜ったまま働けるボード。
思考を声で流し込むと、AI が整理して見える化する。人は見て決め、決めたことはそのまま実行に流れていく。

企画書：https://claude.ai/artifact/1K7uGG7NUQVTWx8FHFjxpb

## 入れる

要るのは Node 20 以上と、入れてログインした [Claude Code](https://docs.claude.com/en/docs/claude-code/setup)（エージェントはどれも Claude Code で動く）。clone もアカウントも要らない。

```sh
brew install node                        # Node がなければ（Mac）。npm も一緒に入る
npm i -g github:yuta4030/dyve#v0.3.0     # dyve コマンドを入れる。版はタグで固定する
```

入れずに試すだけなら `npx github:yuta4030/dyve#v0.3.0 serve`。更新は版を変えて `npm i -g` し直す（版ごとの変更は [CHANGELOG](CHANGELOG.md)）。
`serve` は最初に Claude Code が動くかを確かめ、動かなければ何をすればよいかを出して止まる（`--no-agents` なら確かめない）。

## 使い方

```sh
dyve serve --room ~/code/myrepo   # ボードを立てる（一つだけ）
open http://127.0.0.1:4740/        # 画面
```

- トークの欄に話すか書く。止まって間があくか Enter で発言として置かれる（改行は Shift+Enter）。OS の音声入力（Mac の音声入力、Windows の Win+H）でも、ブラウザが対応していれば「マイク」でも話せる
- 発言が来るとすぐ、清書係（起こしっぱなし）が誤変換を直す
- 間があくと、マネージャが起きて「いまの要点」を書き換え、仕事を見つけたら控室に取り次ぐ
- 取り次がれた仕事は、名前のあるタスクエージェント（アリス、ボブ…）が `--room` のディレクトリで片付け、結果を元の発言の横に置く
- 特定の相手に確実に届けたいときは、状況のアイコンを押してから話す。入力欄に「→ ボブ」と出て、外すまで（もう一度押す・✕・Esc）その人宛てになる。宛てた発言はボードがそのまま相手に渡す。働いていれば終わってから、前の仕事の続きとして
- 声で名前を呼んでもよい（「アリス、それもういい」）。こちらはマネージャが聞き取って取り次ぐ

| オプション | 既定 | 意味 |
|---|---|---|
| `--port` | 4740 | ボードのポート |
| `--data` | `~/.dyve/board.jsonl` | 操作ログ。エージェントのログは同じ場所の `logs/` |
| `--room` | いまのディレクトリ | 控室のエージェントが働くディレクトリ |
| `--config` | `~/.dyve/config.json` | 設定（下の「エージェントを自分好みにする」） |
| `--agents` | `~/.dyve/agents` | エージェントの指示の置き場 |
| `--names` | 設定の team／アリス…フランク | 控室のエージェントの名前をカンマで（例：`--names マイ,ケン`） |
| `--pause` | 4000 | 最後の発言からマネージャを起こすまでの間（ミリ秒）。清書係が走っていれば、終わってから起こす |
| `--scribe-pause` | 1000 | 発言から清書係に渡すまでの間（ミリ秒） |
| `--slots` | 3 | 同時に働くタスクエージェントの数 |
| `--scribe-model` | `haiku` | 清書係のモデル（`claude --model` に渡す） |
| `--manager-model` | `sonnet` | マネージャのモデル |
| `--task-model` | claude の既定 | 控室のタスクエージェントのモデル（例：`opus`） |
| `--claude` | `claude` | Claude Code のコマンド |
| `--no-agents` | | エージェントを起こさない（画面だけ） |

どのオプションも、コマンド ＞ 設定（config.json）＞ 既定 の順に決まる。

## エージェントを自分好みにする

設定は `~/.dyve/config.json`（`--config` で変えられる）、指示の本文は `~/.dyve/agents/<名前>.md`（`--agents`）。依存を持たないので、設定は JSON、指示はただの Markdown。
どちらも置かなければ既定のまま。置き場は初めて立てたときに README つきで作られる。変えたら立て直すと効く。

```json
{
  "room": "~/code/myrepo",
  "slots": 3,
  "task":    { "model": "opus", "prompt": "~/notes/research.md" },
  "scribe":  { "model": "haiku", "pause": 1000, "prompt": "~/notes/words.md" },
  "manager": { "model": "sonnet", "pause": 4000, "cwd": "~/.dyve/staff", "prompt": "~/notes/CLAUDE.md" },
  "team": [
    { "name": "マイ", "initial": "M", "model": "opus", "room": "~/code/docs" },
    { "name": "ケン" }
  ]
}
```

- 上の段：`port`・`data`・`room`・`claude`・`slots`・`agents` はコマンドのオプションと同じ
- `task`：控室の全員。`model`（`--task-model` と同じ）・`prompt`
- `scribe`・`manager`：`model`・`pause`（ミリ秒）・`cwd`（起きるディレクトリ）・`mode`・`prompt`
- `team`：控室の顔ぶれ。並んだ順に仕事を受け、書くと既定の六人の代わりになる。`name`（要る）・`initial`（アイコンの頭文字）・`model`・`room`（働くディレクトリ）・`mode`・`prompt`
- `prompt`：指示として読ませるファイル（育てている CLAUDE.md など）。一つなら文字列、いくつもなら配列
- 指示の本文は、`prompt` のファイル、置き場の `<名前>.md`（`scribe.md`・`manager.md`・`マイ.md`）の順につなぎ、dyve の既定の指示の後ろに足す。`mode: "replace"` なら差し替える。`{{names}}` は控室の名前の並びになる
- パスの `~` はホーム、相対パスは config.json のあるところから
- `room` が別の人の開発の仕事は、その部屋から worktree を切り出し、受け入れたらその部屋に取り込む
- エージェントは普通の Claude Code として起きるので、`~/.claude/CLAUDE.md` や、働くリポジトリの CLAUDE.md はいままでどおり読まれる

### チームの設定を取り込む

いくつものチームに入っている人は、チームごとに育てた設定を一つの dyve に取り込める。ボードは一枚のまま、全チームの仕事をそこで扱う。

```json
// ~/.dyve/config.json（個人）
{ "teams": ["~/code/algr", { "path": "~/code/k2down", "rename": { "アリス": "アリサ" }, "model": "opus" }] }
```

```json
// ~/code/algr/.dyve/config.json（チーム。リポジトリに入れて育てる）
{
  "name": "algr",
  "task":    { "model": "sonnet", "prompt": "conventions.md" },
  "scribe":  { "prompt": "words.md" },
  "manager": { "prompt": "triage.md" },
  "team": [{ "name": "マイ" }, { "name": "ケン", "model": "opus" }]
}
```

- 控室：全チームの顔ぶれを合わせる。働く場所の既定はそのチームのリポジトリ。ボードには `マイ@algr` のように残り、この名前は変えない（`name` の既定はリポジトリのディレクトリ名）
- 清書係：チームの指示（言葉の言い換えなど）、そのあとに個人の指示
- マネージャ：チームごとの節（チームの指示・顔ぶれ・リポジトリ）を渡す。どのチームの仕事かを見分け、`data.team` を付けて取り次ぐと、そのチームの空いている人が受ける
- 控室のチームの人：チームの指示、そのあとに個人の指示（`~/.dyve/agents/マイ@algr.md` も読む）
- どれが勝つか：コマンド ＞ 個人 ＞ チーム ＞ 既定。`teams` の `model` はそのチームの人のモデルを決める
- 名前がぶつかったら、立てるときに端末に知らせ、チームの人を「algr の アリス」のように呼び分ける（頭文字も aA・kA）。ログの名前は変わらないので、過去のボードとつながったまま。呼び名は `rename` で変えられる
- チームの設定はほかの人が書くので、書けるのは `name`・`room`・`task`・`scribe`（`prompt` だけ）・`manager`（`prompt` だけ）・`team`。パスは `.dyve` からの相対で、リポジトリの中だけ。コマンド（`claude`）や置き場、指示の差し替え（`mode`）は個人の設定でしか決められない

`dyve export` で、ボードをそのまま Markdown に書き出す（AI は使わない）。画面の「Markdown に書き出す」も同じ。

## パネルを足す（拡張は利用者側で）

パネルは view（描き方）とデータでできている。dyve 本体の view は最小限で、それ以外は `~/.dyve/panels/views/<名前>.js` に置く（置き場は初めて立てたときに README と見本つきで作られ、git で履歴を持つ）。

- 「こんなパネルが欲しい」と話すと、マネージャがパネルの仕事として取り次ぎ、アリスたちが置き場に view を書いてパネルを置く。書き換えると画面はすぐ描き直す
- 利用者の view は sandbox の iframe の中で描く。ボードの API には触れない
- データの流し込み方：
  - パネルの data に直接（エージェントは MCP で）
  - `df -h | dyve put p12`：標準入力をそのパネルのデータにする（JSON なら JSON で）
  - `dyve add --view bars --shell "du -s * | sort -n" --every 60`：shell コマンドの結果を流し込むパネルを置く
  - エージェントが置いた shell コマンドは、人が画面で「実行を許可」を押すまで走らない。AI がコマンドを変えたら許可は外れる
- どのパネルも「タイルに出す」で、自分のタイルにできる
- 使う・使わない、既定の大きさ、消すは「パネルの管理」で（下の「ボードとパネルを管理する」）

## dyve で dyve を開発する

使う dyve と作る dyve を分ける。取り込んだ変更が壊れていても、使っているボードは落ちない。

```
cd ~/code/dyve
node bin/dyve.js app                                   # 使う dyve を ~/.dyve/app に切り出す（いまのコミット）
node ~/.dyve/app/bin/dyve.js serve --room ~/code/dyve  # 使う dyve で、作る側を部屋にして立てる
```

- 「直して」「作って」と話すと、マネージャが開発の仕事（`data.write: true`）として取り次ぐ
- 開発の仕事は、部屋のいまの HEAD から切り出した worktree（`~/.dyve/work/<仕事>-<時刻>`）とブランチ（`dyve/<仕事>-<時刻>`）の中で書き、`node --test` を走らせてコミットし、結果を提案として置く。push はしない
- 取り込むかは人が決める。提案の「受け入れる」を押すと、そのブランチを部屋のいまのブランチにマージコミット（`--no-ff`）で取り込み、作業場とブランチを片付けて、結果をボードに置く。ぶつかったら取りやめて元に戻す。戻したいときは `git revert -m 1 <コミット>`
- 取り込んだ変更を使っている dyve に反映するには、dyve 設定の「更新して再起動」。部屋から切り出した dyve のときだけ更新し、npm で入れた dyve は立て直すだけ（部屋のコミットで上書きしない）。`~/.dyve/app` を部屋のいまのコミットに更新して、立て直す（`serve` は見張り役が本体を子として起こしているので、落ちても同じ端末で立ち直る）

## ボードとパネルを管理する

dyve 設定のアイコンから、別のタブで管理のページを開く。話している方のタブはそのまま動き続ける。

**ボード（`/boards`）**：`--data` と同じディレクトリの `*.jsonl` が一枚ずつのボードになる。

- 呼び名・最初の発言・話題・要点・更新日時・受け入れ待ちの数で見分け、検索できる
- 開く、新しいボードにする（いまのボードの操作ログは残る）。切り替えると、前のボードの清書係・マネージャ・控室は止まる
- 呼び名を付ける：同じディレクトリの `boards.json` に持つ。ボードの名前（ファイル名）は id なので変えない
- しまう：`archive/` に移すだけでログは消えず、いつでも戻せる。いま開いているボードはしまえない

**パネル（`/panels`）**：view の種類ごとに、実際に使ったデータで描いた小さな絵と設定が並ぶ。絵を押すと大きく出る。それぞれ開くといまのボードのパネルを一覧して外せる。

- 使う・使わない（自分の view だけ）：使わないにすると、そのパネルは画面から隠れ（データは残る）、人も AI も新しく置けなくなり、コマンドの流し込みも止まる。人の判断待ちのものと、下に何か付いているものは隠さない
- 既定の大きさ（ピクセル）：話題の中のパネルと、新しくできるタイルに効く。話題のタイルの大きさは `topic` で決まる。すでに置いたタイルや自分で動かしたものの大きさは変えない
- 消す（自分の view だけ）：パネル置き場の `trash/` に移して履歴に積むだけで、いつでも戻せる。残ったパネルは JSON のまま見える
- 設定は `~/.dyve/panel-settings.json`。パネルの仕事のエージェントが書けるパネル置き場の外に持つ

## Claude Code のプラグインとして入れる

ボードを立てるのは `dyve serve`。プラグインは、普段使っている Claude Code から、立っているボードを読み書きするためのもの。このリポジトリはそのままマーケットプレイスになっている（公開リポジトリなので、入れるのにログインは要らない）。

```
/plugin marketplace add yuta4030/dyve
/plugin install dyve@dyve
```

中身は、ボードへの接続設定（`.mcp.json`）、清書係とマネージャの定義（`agents/scribe.md`・`agents/manager.md`）、控室で使うスキル（`skills/backroom`）。
ユーザーの好みは、自分の CLAUDE.md に書けば重なる。

## しくみ

```
Panel { id, by, view, data, about?, state?, to?, pinned }
Op    { seq, at, by, type: add | edit | drop, panel, reason? }
```

- **ボード**（`src/board.js`）：操作ログを頭から当てた結果のパネルの並び。操作は add・edit・drop だけ
- **印**はデータに持たず導く。未着手＝結果の付いていない仕事、受け入れ待ち＝提案、知らせ＝人が最後に見たあとに AI が置いた・変えたパネル
- **MCP の口**（`POST /mcp?as=<名前>`）：エージェントが人と同じ操作でボードを読み書きする。道具は `board_read`・`board_view`（全体の絵）・`panel_view`（一枚の絵）・`panel_add`・`panel_edit`・`panel_drop`・`panel_history`・`board_layout`（人が画面でできるレイアウトの操作を全部）・`word_add`（辞書に足す）
- **起こし係**（`src/waker.js`）：発言を起こしっぱなしの清書係に流し込み、間があいたらマネージャを一人だけ起こし（読むものは指示に入れて渡す）、仕事が置かれたら名前のあるエージェントを起こす。同じ仕事を同時に二つ走らせない。使ったトークンと費用を数える
- **配役**（`src/crew.js`）：設定（`~/.dyve/config.json`）と指示の置き場（`~/.dyve/agents`）を立てるときに一度読み、名前・起きる場所・モデル・指示を決める。前置きは dyve の定義に利用者の指示を足したもの
- **キャッシュ**：前置き（system prompt・道具・定義）は役ごとに固定し、変わるものは指示の側に置く。清書係とマネージャは空の作業場（`~/.dyve/staff`、設定の `cwd` で変えられる）で、控室は `--room`（設定の `room`）で `--exclude-dynamic-system-prompt-sections` を付けて起こす
- **管理のページ**（`src/manage.html`）：`/boards` と `/panels`。人だけが使う
- **画面**（`src/ui.html`）：パネルの JSON を view（Web Components）に流し込んで描く。view は `say`・`text`・`list`・`table`・`task`・`topic`・`summary`。画面は全部タイル（トーク・いまの要点・状況・残量・dyve 設定と、話題ごとのタイル）を上下左右に広がるキャンバスに並べたもので（右下の全体マップで見渡し、dyve 設定へ戻れる）、置き場所・大きさ・中身の拡大縮小・固定・最小化（見出しだけ残す）・閉じる・ます目の細かさ、話題の中のパネルの置き場所・大きさ・最小化・畳みはボードの view `layout` のパネルに持つ（固定は人だけが決め、それ以外はエージェントも全部変えられる）。話題の中のパネルもタイルと同じます目で動かし・大きさを変えられる。人の発言はトーク、`summary` は要点、それ以外は話題ごと（話題がなければ元の発言ごと）に一枚のタイルにする。新しい話題のタイルは、ほかのタイルを押しのけずに一画面の幅の中で上から空いているところへ出て、知らせがあれば見出しに印が付く。話題のタイトルはタイルの見出しに出す。仕事の結果は about で仕事を指したまま、画面では仕事と並べて話題の直下に出す。宛てた相手の短い返事はトークの発言の下にも出す。アイコンは状況・トーク・宛先で同じもの（`ini()`）を使う。残量は claude が流してくる利用枠（5 時間枠・週）から出す

### 立場ごとにできること

| 操作 | 人（画面） | AI（MCP） |
|---|---|---|
| パネルを置く・書き換える | できる | できる（reason が要る） |
| ピン留めされたパネルを書き換える・外す | できる | 断られる（pinned） |
| ピン留めする・外す | できる | 断られる（forbidden） |
| 提案を受け入れる（proposal → done） | できる | 断られる（forbidden） |
| 人が置いたパネルを外す | できる | 断られる（forbidden） |
| タイルと話題の中のパネルの見た目を変える（移動・大きさ・最小化・閉じる・拡大率・タイルに出す・畳む・ます目・並びを戻す） | できる | できる（reason が要る） |
| 固定したタイル・ピン留めしたパネルと、その中のものの見た目を変える | できる | 断られる（pinned） |
| タイルを固定する・外す | できる | 断られる（forbidden） |
| 発言を合成する（`into`）・分ける | できる | できる。宛てた発言・ピン留めは断られる |
| 辞書に足す | できる | できる。人が書いた項目と人が消した言葉は断られる（forbidden） |
| 辞書から消す | できる | 断られる（forbidden） |

拒否コードは pinned・forbidden・not_found・conflict・invalid。

### 控室のエージェントに許す道具

取り消せないことは人が決める。清書係は発言の書き換えと辞書への追記だけ、マネージャはボードだけ。控室のタスクエージェントは Claude Code の `--permission-mode auto` で動き、危ない操作はその判定が止める。

- 調べものの仕事：Edit・Write・NotebookEdit を禁止。シェルでの書き込みは `auto` の判定に任せるので、完全にはふさいでいない
- 開発の仕事：仕事ごとの git worktree で書き、取り込むかは人が決める
- どの仕事でも `git push`・`git remote`・`git reset`・`rm` は禁止（`--disallowedTools`）

外に届くことは提案（state `proposal`）として置き、人が受け入れる。

### 辞書と絵

- **辞書**（`src/words.js`）：`~/.dyve/words.jsonl`。追記だけのログで、全部のボードで共通。エージェントが `word_add` で足し、清書係が使う。dyve 設定の情報のボタンから見る・足す・消す
- **絵**：`board_view` は枠と番号の PNG と対応表（日本語は対応表に）。`real: true` で本当の画面の絵も付く。`panel_view` はブラウザのヘッドレスで撮る。ブラウザは PATH と決まった場所（WSL の Windows 版を含む）から探す。設定の `browser` か環境変数 `DYVE_BROWSER` で指定でき、なければ絵の代わりに中身を返す

3. PR をマージする。main の版にまだタグがなければ、CI（`.github/workflows/release.yml`）が `v<版>` のタグと GitHub Release を作る。Release の本文は CHANGELOG のその版の節
4. README の「入れる」の版を新しいタグに直す
